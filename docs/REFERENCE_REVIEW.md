# Проверка четырёх диалогов

Цель — получить небольшой независимый набор **ручных эталонов** для оценки ASR,
принадлежности слов и временных границ. Автоматические результаты не считаются эталонами.

## Материалы

- `data/r001.wav` … `r004.wav`: записи из main, суммарно около 12 минут.
- `data/rNNN.draft.json`: исходные черновики сохранены без замены.
- `data/review/rNNN.candidate.json`: новые модельные кандидаты для ручной проверки.
- `data/review/review-status.json`: происхождение, SHA-256 аудио и кандидатов,
  расхождения моделей, неизвестные голоса и временные корректировки.
- `artifacts/reference-review/original-draft-audit.json`: структурный аудит исходников.

Первичная дополнительная ASR — локальная полная Whisper large-v3 q5_0.
Для сравнения запускается Whisper podlodka turbo q4_0, используемая в приложении.
Ни один из этих результатов сам по себе не является правильным ответом.
Диаризация — pyannote/WeSpeaker и настоящий Kotlin-движок VoiceMind, включая
короткие уточняющие окна; число людей не подсказывалось из черновиков.
Времена слов Whisper приближённые, и на границах нужна проверка по звуку.

## Как проверять

1. Откройте разметчик `index.html` через локальный HTTP-сервер или доступный HTTPS-хостинг.
   Для переноса редактора нужны оба файла: `index.html` и `labeler-core.js` рядом;
   библиотека записей и новые кандидаты находятся в `data/`.
2. Выберите запись. Кандидат имеет статус черновика; подтверждённые ручные правки
   из вашего браузера автоматически не заменяются новой модельной версией.
3. Прослушайте **всё** аудио. Очередь замечаний помогает найти спорные места,
   но отсутствие замечания не означает, что фрагмент правильный.
4. Исправьте слова, короткие ответы, имена, число людей и момент смены голоса.
   При смене человека создайте новую реплику; последовательные слова одного
   человека объединяйте. Наложения проверяйте особенно внимательно: одинаковая
   смесь звука не даёт права продублировать весь текст на обоих участников.
5. Числа запишите словами так, как они произнесены. Не добавляйте редакторские
   пояснения и не восстанавливайте неразборчивые слова по смыслу.
6. Отметьте «Прослушано: текст, говорящий и границы проверены» для каждой реплики.
   Правка текста, личности или времени сбросит отметку. Разрезание выполняется
   по курсору в тексте; если плеер внутри интервала — по его текущему времени.
7. Сохраните проверенную разметку. Для незавершённой работы есть отдельная
   выгрузка черновика. Итоговый JSON содержит только четыре поля контракта;
   служебные сведения не попадают в `transcript`.
8. Второй человек перепроверяет короткие ответы, наложения, неизвестные места
   и всю разметку хотя бы один раз перед фиксацией набора. Запишите имя проверившего
   и SHA-256 итогового файла отдельно в манифесте проверки.

Отметки в редакторе фиксируют заявление проверяющего; они не являются автоматическим
доказательством правильности. В этой ветке нет файлов, объявленных идеальным эталоном
без человеческого прослушивания. `unknown` и `overlap` в кандидате требуют ручного
решения; проверенный экспорт допускает личности вида `speaker_1`, `speaker_2` и т.д.

## Воспроизводимость и разделение данных

Не используйте этот набор для обучения Gemma, подбора подсказок и настройки порогов,
если планируете заявлять его независимой итоговой проверкой. Для обучения нужен
отдельный набор без этих разговоров и повторов тех же фрагментов.
После первого использования для настройки набор становится диагностическим;
для подтверждения качества потребуется новый, ранее не просмотренный набор.

Инструменты `audit_references.py` и `prepare_review_candidates.py` не вычисляют WER
относительно машинного кандидата как будто он правильный. WER/DER публикуются
только после фиксации ручного эталона. Исходные эталоны не подаются модели при
распознавании; допустимо только сравнение результатов отдельным скорером.

```bash
node --test tests/*.test.cjs
python3 -m unittest discover -s scripts -p 'test_*.py' -v
python3 scripts/audit_references.py data --output /tmp/original-audit.json
python3 scripts/prepare_review_candidates.py --workspace /path/to/local-evidence
```

Рабочие голосовые embeddings и многогигабайтные веса остаются локально и в Git
не включаются. Сравнение на компьютере не считается замером Android RTF.

## Полный повтор обработки

Нужны собранный whisper-cli с Metal, JDK 17, подготовленный Android Gradle-кеш
и ML Python с numpy/onnxruntime. ONNX-файлы проверяются по SHA-256 кодом захвата.
Веса full large-v3 q5_0 получают из ggerganov/whisper.cpp; его SHA-256 закреплён
в скрипте. Пути ниже — аргументы вашей локальной установки:

```bash
/path/to/ml-python scripts/run_reference_review.py \
  --workspace /tmp/reference-evidence \
  --whisper-cli /path/to/whisper-cli \
  --large-model /path/to/ggml-large-v3-q5_0.bin \
  --turbo-model /path/to/ggml-whisper-podlodka-turbo-q4_0.bin \
  --onnx-models /path/to/onnx-models \
  --java-home /path/to/jdk17 \
  --ml-python /path/to/ml-python
python3 scripts/verify_review_corpus.py
```

Новая обработка создаёт новые кандидаты и сбрасывает служебный статус проверки
до машинного черновика. Ручной эталон храните отдельным `.reference.json` и не
перезаписывайте его модельными результатами.
