## Методика замеров на Android (план для `results.csv`)

- **Наборы.** `test_data/real` (4 живые записи с эталонами) и синтетика (31 диалог, эталоны `ref/*.json` с точной разметкой времён).
- **Условия.** Эмулятор или телефон, 4 ГБ, авиарежим, чистая установка конкурсной APK, один файл за раз, холодный старт модели учитывается отдельно.
- **Метрики.** WER: `scripts/evaluate.py` (слова без знаков, `casefold`, ё→е) и `strict_wer.py` (со знаками и регистром). RTF: время от выбора файла до
  готовых реплик с метками говорящих, делённое на длину записи. DER: `src/android/tools/device_test/diar_score.py`.
- **Столбцы `results.csv`:** идентификатор, время UTC, commit, APK, устройство, файл, длительность, время обработки, RTF, WER, DER, авиарежим, успех, примечание.
- **Ограничения.** Синтетика озвучена одним синтезатором (разные скорость и высота, не разные люди) и плохо оценивает пунктуацию;
  эмулятор работает на процессоре компьютера и не показывает скорость, нагрев и память телефона; эталоны живых записей размечены человеком по
  машинным черновикам (возможно смещение), у r003 и r004 границы реплик машинные и для проверки временных меток не годятся.

## Методика (общая)

Проверки двух видов: автоматические (Gradle-тесты, Python-скрипты оценки) и сквозной прогон приложения на
Android. Для точности: WER по эталонным расшифровкам (`test_data/`), DER для диаризации (инструменты в
`src/android/tools/device_test`), RTF как время обработки к длине записи. Сырые измерения собираются в
`artifacts/test-results/results.csv`. Эталоны размечены человеком по исходным машинным черновикам.

## Сквозной прогон на эмуляторе (8 ноября)

Сборка LIGHT (модели внутри APK), эмулятор Android 15 (API 35, ARM64, 4 ГБ памяти, CPU без Vulkan),
включён авиарежим. Результаты:

- Первый запуск без интернета: экран «Подготовка к работе» скопировал 905 МБ моделей, приложение открылось.
- Импорт `r002.wav` (139 с) и расшифровка без сети: 26 сегментов, 1818 символов, около 103 с от выбора файла

- WER и DER для этого прогона не считались. Экспорт JSON в этом прогоне не проверялся.

Строка добавлена в `artifacts/test-results/results.csv`. Проверка на физическом Android остаётся впереди.

## Воспроизведение

```bash
cd src/android
./gradlew testStoreDebugUnitTest assembleStoreHackathon
cd ../..
python3 -m unittest discover -s scripts -p 'test_*.py' -v
python3 scripts/evaluate.py exported.json --reference reference.json --elapsed-seconds 42 --audio-seconds 60
```

Числа 42/60 в примере команды — только пример аргументов, не результат измерения.
Скорер оценивает лексический WER без пунктуации, с casefold и ё→е. Он не считает DER
и не маскирует ошибки личности под высокий WER-балл. Для DER используйте инструменты
src/android/tools/device_test и соответствующую независимую разметку.

На данном Mac host-компилятор Vulkan потребовал `SDKROOT=.../MacOSX15.4.sdk`,
`MACOSX_DEPLOYMENT_TARGET=15.0` и SDK/CMake/bin в PATH из-за несовместимости
установленного по умолчанию MacOSX27 SDK с linker. Это настройка компьютера сборки,
не требование Android-пользователя.
