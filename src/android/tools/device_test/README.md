# Тесты на телефоне

## Независимая проверка разделения голосов

`prepare_diarization_benchmark.py` готовит небольшой фиксированный набор из
официальных тестовых аудио VoxConverse и исправленной разметки v0.3. Аудио
скачивается диапазонами HTTP, без загрузки всего четырёхгигабайтного архива;
проверяются CRC, формат WAV и SHA-256. Нужен ZIP разметки из
[репозитория авторов](https://github.com/joonson/voxconverse).

```bash
python3 tools/device_test/prepare_diarization_benchmark.py annotations.zip tools/device_test/assets/private/quality-run
# Другая, непересекающаяся выборка для подтверждения, не для подбора параметров:
python3 tools/device_test/prepare_diarization_benchmark.py annotations.zip tools/device_test/assets/private/quality-confirmation --skip-per-count 4
```

Используйте Python-окружение с numpy/onnxruntime и локальные проверенные ONNX-модели:

```bash
JAVA_HOME=/path/to/jdk /path/to/ml-python tools/device_test/run_diarization_benchmark.py tools/device_test/assets/private/quality-run
# Дополнительно: реальное распознавание слов локальным whisper.cpp.
# --whisper-cli /path/to/whisper-cli --whisper-model /path/to/model.bin --language en
python3 -m unittest discover -s tools/device_test -p 'test_diar*.py' -v
```

Стенд прогоняет CPU ONNX, настоящий Kotlin-движок, дополнительные короткие
окна и повторную кластеризацию. В модель не передаются эталонные границы,
личности или число людей. Метки читает только отдельный скорер. Отчёт
`quality-report.json` содержит DER без collar с наложениями, ошибку числа людей,
возврат редких голосов и принадлежность коротких реплик. Короткие/редкие реплики
оцениваются с одной перестановкой личностей для всей записи: отдельное
переназначение каждой реплики не скрывает ошибки.

`word_interval_attribution` оценивает принадлежность распознанных слов только
на интервалах с минимум 80% эталонной речи одного человека. Наложения, спорные
границы и нулевые длительности считаются отдельно; неопределённая метка в
подходящем для оценки слове считается ошибкой. Это не WER и не полная ручная
пословная разметка. Равномерные диагностические пробы никогда не считаются словами.

`make_diarization_stress.py` создаёт отдельные воспроизводимые варианты: шум
10 дБ, ослабление на 18 дБ, вставленная пауза 30 с и тишина. Это искусственные
возмущения человеческой речи; настоящий дальний микрофон проверяется отдельно
на AMI Array1-01 с разметкой, полученной из ручных аннотаций.

Диагностический набор, на котором обнаруживали или исправляли ошибку, больше
не является независимым подтверждением. Для окончательной проверки используется
следующая выборка, не просмотренная при изменении правил. При регрессии нельзя
просто обновлять эталон до нового результата: отдельно проверяются известные
длинные записи и монтаж с подтверждёнными тремя людьми.

Эти замеры выполняются **на компьютере**. Время Android, нагрев, расход батареи,
импорт M4A и восстановление после выгрузки проверяются только на устройстве.
Сохранённые отчёты старых сборок не подтверждают прогон новой версии.

Повторное разделение сохраняет текущий отредактированный текст; вставленные
слова без акустической привязки получают неопределённого говорящего. Для
переименования используется сохранение в хранилище и Fragment Result API,
поэтому результат не зависит от восстановленного после поворота callback.
Изменение поддержки коротких голосов обновляет ключ кеша до
`evidence-v4-boundaries2`: старое уточнение, рассчитанное для другого набора
голосов, не принимается как завершённое. Первый анализ после обновления
потребует повторного вычисления; последующие используют новые признаки.

Проверки, которые нельзя сделать на компьютере: настоящие модели, настоящий
Android Keystore, скорость на телефоне, перенос старых данных. Прогонять перед
каждым релизом на телефоне по USB (`adb devices` должен его видеть).

## Что проверяется

| Команда | Что | Как оценивается |
|---|---|---|
| `run.py migration` | перенос записей ≤3.9 (JSON) в Room на копии реальных данных | каждое поле каждой записи до и после |
| `run.py asr` | весь конвейер записи (нарезка кусками, VAD, Whisper, фильтр галлюцинаций) на 10 эталонах: синтетика в разных условиях и Golos | WER по эталону, скорость (RTF) |
| `run.py llm` | «Выделить главное» и вопрос к записи на каждой скачанной модели | найдены ли ожидаемые задачи (`data/llm/expected.json`), нет ли лишних на тексте без задач, время |
| `run.py mirror` | скачивание с зеркала кодом приложения: редиректы GitHub, allowlist хостов, SHA-256 | файл совпал побайтно |

Результаты — в `tools/device_test/out/`, повторный отчёт — `run.py report`.

## Разделение голосов: измерять DER, а не только целостность фраз

`run.py diar` показывает диагностические ошибки внутри фраз. Эта статистика не
проверяет глобальную личность говорящего: назначение всех реплик одному человеку
может выглядеть безошибочным. Для оценки качества нужны реальные speaker_id.

После пересборки instrumentation-приложения `EngineEvalDeviceTest#diarization`
сохраняет в `diar.json` поле `turns`: акустические интервалы в миллисекундах,
включая одновременную речь. Поле доступно для пути pyannote; пустое поле при
недоступной разметке означает отсутствие акустического результата. Пословные
`units` не заменяют интервалы речи при вычислении DER.

Эталон — JSON-массив `[start_ms, end_ms, speaker_id]`. Имена условные, но один
человек должен иметь один и тот же ID на протяжении всей записи. Одновременную
речь размечайте двумя пересекающимися интервалами. Пример:

```json
[[0, 1000, "Анна"], [800, 1600, "Игорь"], [2000, 3000, "Анна"]]
```

```bash
python3 tools/device_test/diar_score.py reference.json tools/device_test/out/diar.json --recording dialog_0
python3 -m unittest discover -s tools/device_test -p test_diar_score.py -v
```

Скорер использует одну оптимальную перестановку говорящих для всей записи,
не пропускает наложения и не допускает погрешность на границах (collar=0).
Показывает missed/false alarm/confusion отдельно; DER может превышать 100%.
Без эталонной речи DER не определён (`null`). Поддерживается до восьми голосов.
Акустические `turns` — гипотеза текущего конвейера, а не ручная разметка.

Перед выбором новых весов/порогов сравнивайте одну и ту же отложенную выборку:
монолог, 2/3/5 голосов, похожие голоса, короткие ответы, дальний микрофон, шум,
одновременная речь, возвращение участника после долгой паузы, 30–60 минут.
Считать отдельно DER, точность числа людей, ошибки принадлежности слов, RTF,
пиковую память и нагрев на целевом телефоне. RTF — время обработки / длина аудио;
первый запуск с загрузкой моделей и повторные запуски измеряются отдельно.
Порог кластеризации и профильные пороги подбираются на development-наборе,
итоговая оценка — на других записях. Синтетика и JVM-тесты проверяют алгоритмы,
но не подтверждают качество моделей или скорость на Android.

### Акустический smoke-тест на отдельной store-debug установке

Эта проверка использует `ru.guzlikvoice.app.dev`, не рабочее приложение. Для
`run.py` выше используется другой flavor — `com.example.guzlikvoice.dev`.

```bash
./gradlew assembleStoreDebug assembleStoreDebugAndroidTest
adb install -r app/build/outputs/apk/store/debug/GuzlikVoice-v4.0.7-dev-store-debug.apk
adb install -r -t app/build/outputs/apk/androidTest/store/debug/app-store-debug-androidTest.apk
# Явно разрешённая загрузка двух публичных ONNX-моделей, проверка SHA-256:
adb shell am instrument -w -e class com.example.guzlikvoice.EngineEvalDeviceTest#prepareDiarizationModels -e downloadModels true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
python3 tools/device_test/make_acoustic_smoke.py
adb shell mkdir -p /sdcard/Android/data/ru.guzlikvoice.app.dev/files/eval/diar
adb push tools/device_test/assets/diar/*.s16 /sdcard/Android/data/ru.guzlikvoice.app.dev/files/eval/diar/
adb shell am instrument -w -e class com.example.guzlikvoice.EngineEvalDeviceTest#diarizationAcoustics ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
mkdir -p tools/device_test/out
adb pull /sdcard/Android/data/ru.guzlikvoice.app.dev/files/eval/out/diar-acoustics.json tools/device_test/out/
python3 tools/device_test/summarize_acoustic_smoke.py tools/device_test/out/diar-acoustics.json --output tools/device_test/out/acoustic-summary.json
```

Для отдельного случая добавьте instrumentation-параметр `-e only tts_three_speakers`,
для известного числа людей — `-e numSpeakers 3`. Акустический тест использует
равномерные пробы по 100 мс, не подаёт эталонные личности или границы фраз в модель
и не запускает Whisper. Успех JUnit означает отсутствие технического сбоя;
неверное число голосов и ошибки разметки видны в отчёте.

Голоса Daniel/Samantha/Karen — синтез macOS. Эталонные границы — границы клипов,
не ручная разметка звучащих фонем; внутренние паузы тоже могут попасть в missed
speech. Поэтому DER здесь диагностический. Пересозданные клипы надо передать на
телефон заново; старые результаты нельзя оценивать по новым клипам. Для выводов
о продуктовой точности нужны человеческие записи и независимая разметка.

### Повторное разделение и проверка полного фонового задания

После извлечения признаков приложение держит последнюю запись в RAM (до 8 МиБ).
Дополнительно контрольные точки сохраняются в `noBackupFilesDir/diarization`:
AES-256-GCM, отдельный ключ Android Keystore, AAD с версией и id записи,
атомарная замена файла. Открытый временный файл с признаками не создаётся. Не более трёх
записей / 96 МиБ; одна контрольная точка ограничена 32 МиБ. Android backup
и ручной архив GuzlikVoice эти файлы не включают.

Контрольная точка создаётся перед первым окном, затем каждые 10 окон и после
последнего. Результаты принимаются по порядку: восстановление пропускает только
полностью сохранённый префикс. Ошибка модели останавливает обработку, а не
создаёт разметку с молча пропущенным аудио. Пустой файл `.pending` отмечает незавершённое задание; при обычном запуске
не требуется читать отпечатки уже готовых записей. При открытии приложения незавершённые
задания продолжаются; из фонового `Application.onCreate` службы не запускаются.
Системный лимит foreground-службы приостанавливает задания с сохранением прогресса.
Для локальной обработки используется тип `dataSync`, для записи — `microphone`.
См. [требования Android](https://developer.android.com/develop/background-work/services/fgs/service-types).

Полная контрольная точка позволяет менять число голосов после перезапуска
без декодирования, Whisper и ONNX. Повторная обработка в том же процессе
сначала проверяет RAM и не читает контрольную точку с диска. При восстановлении
уже прочитанный снимок передаётся заданию без повторной расшифровки. Размер/время изменения аудио, версии файлов
моделей и формат признаков входят в ключ. Отмена, удаление, включение защиты
записи и очистка данных удаляют контрольную точку и запрещают позднюю запись
по устаревшему токену. Повреждённые файлы отвергаются. Незавершённый результат
не заменяет текст. Итог сохраняется сравнением с исходным текстом под блокировкой,
поэтому новые ручные правки, удаление или защита записи не будут затёрты.

`DiarizationReplayDeviceTest` — opt-in стенд для локальной диагностической копии:
`-e historyReplay true`. Читает `eval/history/evidence.json`, `segments.json` и
`expected-v2.json` во внешнем каталоге **debug**-приложения (другой файл можно
выбрать через `-e expected имя.json`). Сравнивает полную
расшифровку по SHA-256 с локальным эталоном и измеряет повторное разделение без
аудио и загруженных моделей. `-e importReviewCopy true` дополнительно требует
`original.mp3`, создаёт отдельную запись в debug-истории и проверяет реальный
`DiarizationJobRunner`, сохранение результата и попадание в кэш. При промахе кэша
тест отменяет задание, чтобы случайно не запустить многочасовую обработку.
Он не обращается к данным рабочего пакета приложения.

Для локального CPU-анализа доступны `capture_evidence_host.py`, `EvidenceSweep.java`
и `EvidenceReplay.java`. Они не отправляют аудио или признаки в сетевые сервисы.
Перед сравнением рантаймов проверять fbank на существующей Kaldi-фикстуре и
сопоставлять границы регионов и косинусное сходство одних и тех же отпечатков.
Время вычисления на Mac не является оценкой скорости Android.

### Короткие ответы, редкие голоса, спорные слова

Квадратичная кластеризация ограничена 1024 наблюдениями. Выборка сохраняет
равномерное покрытие времени и дополнительные группы из акустически необычных
участков. Проекции используются только для выбора: в модель кластеризации
поступают исходные векторы. Слабая группа может быть сохранена как редкий голос
при согласованных признаках из независимых реплик. Несколько перекрывающихся
окон одного события не считаются независимыми репликами. Порог зависит от текущей
модели WeSpeaker и требует проверки на других человеческих записях.

Временная шкала отдельно учитывает последовательную смену и реальную
одновременную речь. В тексте доступны `[Говорят одновременно]` и
`[Говорящий не определён]`. Слабые отпечатки, недостаточное покрытие и близкие
голоса не получают уверенную метку принудительно. Для слова с нулевой длительностью
проверяется акустическое окружение ±80 мс: неопределённая граница не превращается
в уверенный выбор следующего человека. Неполный список слов сохраняет целую фразу.
Это консервативное назначение слов, а не фонетическое forced alignment.

В карточке записи можно выделить фразу долгим нажатием и выбрать «Говорящий».
Меняется только выбранный участок, прежняя метка следующего текста восстанавливается.
Для этой операции модели не запускаются. Изменившийся во время выбора текст
защищён от перезаписи.

### Проверка продолжения, интерфейса и первого анализа на телефоне

```bash
adb shell am instrument -w -e class com.example.guzlikvoice.DiarizationQualityDeviceTest#inferenceResumeAndPerformance -e qualityAudit true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
adb shell am instrument -w -e class com.example.guzlikvoice.DiarizationQualityDeviceTest#spinningComparison -e spinAudit true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
adb shell am instrument -w -e class com.example.guzlikvoice.DiarizationQualityDeviceTest#onnxThreadComparison -e threadAudit true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
adb shell am instrument -w -e class com.example.guzlikvoice.DiarizationUiDeviceTest -e qualityUi true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
```

Первый тест сравнивает 1/2/3 обработчика, прерывает реальную модель после второго
окна и продолжает из зашифрованного файла, проверяет совпадение разметки и отказ
при повреждении шифротекста. Дополнительные тесты сравнивают режим ожидания ORT
и 2/4 потока внутри оператора. Настройка применяется только с заметным выигрышем
и при совпадении интервалов и принадлежности слов. Профиль привязан к устройству
и версии конфигурации. Модели, точность вычислений и шаг анализа не упрощаются.
Отчёты в `eval/out`: `quality-audit.json`, `spinning-audit.json`, `threads-audit.json`;
содержат RTF, время, память и температуру батареи. Замеры на синтезе не являются
оценкой времени для любой человеческой записи.

Для разрешённой локальной истории `GUZLIKVOICE_LOCAL_EVIDENCE` указывает на каталог
с `full-evidence.json`, `full-segments.json` и `expected.json` (проверенное число
голосов и единиц). `LocalEvidenceReplayTest` запускает настоящий Kotlin-движок,
проверяет сохранность слов и создаёт `expected-v2.json` для проверки паритета.
Без переменной окружения тест пропускается. Сравнение SHA подтверждает паритет
двух сред, не точность принадлежности каждого слова.

Проверка восстановления полной истории в отдельном процессе:

```bash
adb shell am instrument -w -e class com.example.guzlikvoice.DiarizationReplayDeviceTest#replayAndJobRunner -e historyReplay true -e importReviewCopy true -e seedOnly true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
adb shell am instrument -w -e class com.example.guzlikvoice.DiarizationReplayDeviceTest#recoverPersistedJobInFreshProcess -e historyRecovery true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
```

Файлы истории находятся только в debug-пакете, `expected-v2.json` должен быть
передан вместе с ними. Второй вызов восстанавливает задание через тот же путь,
что открытие приложения. При неожиданном запуске моделей тест отменяет работу.
Если завершённая контрольная точка уже существует, первый вызов можно заменить
на `DiarizationReplayDeviceTest#seedRecoveryFromCompletedCheckpoint` с
`-e historySeed true`: подготовка не запускает повторную кластеризацию.

### Независимое длинное аудио без подсказки числа говорящих

`LocalAcousticReplayTest` читает `full-evidence.json` из каталога, заданного
`GUZLIKVOICE_ACOUSTIC_EVIDENCE`, и запускает настоящий Kotlin-движок в авто-режиме.
Разметка проверяется на равномерных пробах по 100 мс. Эти пробы не являются
словами или расшифровкой речи. Результат — `full-result.json` и
`expected-acoustics.json` с хешами интервалов и назначений:

```bash
GUZLIKVOICE_ACOUSTIC_EVIDENCE=/absolute/private/fixture ./gradlew :app:testStoreDebugUnitTest --tests com.example.guzlikvoice.LocalAcousticReplayTest
```

Для паритета Android передайте эти два входа (`full-evidence.json` и
`expected-acoustics.json`) в `eval/acoustic/<fixture>/` debug-приложения:

```bash
adb shell am instrument -w -e class com.example.guzlikvoice.EngineEvalDeviceTest#cachedAcousticsParity -e acousticReplay true -e fixture interview-2026-11-04 ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
```

Этот вызов проверяет полную кластеризацию и объединение интервалов. Извлечение
признаков из аудио в нём не запускается: его надо отдельно сверять на одинаковом
PCM через `diarizationAcoustics -e captureEvidence true`. При переносе участков
из длинной записи сравнивайте только окна, полностью лежащие внутри участка;
окна на стыках монтажа содержат другой звук.

На независимом аудио длительностью 2:50:36 автоматический режим выделил три
группы, а Android воспроизвёл все интервалы и 102 364 назначения проб за 4,401 с.
На восьми распределённых по записи участках совпали границы 168 регионов из
40 полных окон; минимальное косинусное сходство признаков — 0,99999999998.
Пользователь подтвердил три разных человека в образцах, но обнаружил смену
двух людей внутри одного фрагмента с единой меткой. Подробная проверка короткими
окнами тоже выявила смешанный отпечаток. Это известная ошибка границы реплики,
а не подтверждение идеального качества при совпадении числа людей. Полной
независимой разметки для DER нет. Частичные человеческие отметки хранятся
только рядом с приватной фикстурой и не используются для выбора числа групп.

### Уточнение пропущенных смен говорящего

Первый проход сохраняет глобальные группы голосов. Если отпечаток длинного
участка похож сразу на два центроида, второй проход извлекает дополнительные
2-секундные отпечатки с шагом 500 мс только в спорных местах. Они не участвуют
в повторном подсчёте людей. Изменение метки требует согласованной поддержки
нескольких окон; речь уточняется внутри исходной маски. Паузы, наложения и уже
найденные реплики короче 2,5 с сохраняются. Неподтверждённый короткий промежуток
между двумя подтверждениями одного голоса может объединяться; уверенная чужая
реплика не объединяется.

Идея использования разных временных масштабов описана в
[NeMo](https://docs.nvidia.com/nemo-framework/user-guide/26.02/nemotoolkit/asr/speaker_diarization/models.html).
В стандартном конвейере [WeSpeaker](https://github.com/wenet-e2e/wespeaker/blob/master/wespeaker/cli/speaker.py)
также используются короткие перекрывающиеся окна. Здесь реализован отдельный
ограниченный второй проход, без добавления модели MSDD или изменения весов.

Короткие признаки и прогресс второго прохода входят в зашифрованную контрольную
точку V4; V5 дополнительно хранит отпечаток исходного текста для защиты
после перезапуска процесса. V3/V4 по-прежнему читаются; ключ обработки обновлён до
`evidence-v4-boundaries1`. Повторное разделение завершённой записи использует
сохранённые короткие признаки. После системной паузы продолжается сохранённый
префикс второго прохода. При конфликте с ручной правкой автоматическое
продолжение прекращается, а правка остаётся в записи. Снимок текста делается
при запуске задания, поэтому защищены и изменения во время ожидания очереди.

Быстрое задание из кеша может закончиться до доставки Android-команды запуска
службы. `RecordingService` подтверждает foreground-запуск и для уже завершённого
токена, затем удаляет уведомление и останавливается, если активных задач нет.
Устаревшая команда при наличии нового задания сохраняет его foreground-защиту.
Это предотвращает отложенный `ForegroundServiceDidNotStartInTimeException`.
Регрессия на устройстве доставляет три уже завершённых старта и ждёт дольше
системного срока, проверяя отсутствие аварии и оставшейся службы:

```bash
adb shell am instrument -w -e class com.example.guzlikvoice.RecordingServiceDeviceTest -e serviceAudit true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
```

Автоматический подсчёт также учитывает временную поддержку обычных кластеров:
для нового слабого голоса недостаточно нескольких почти одновременных
представлений одной короткой реплики. Это исправляет случай, где монтаж из
восьми участков давал восемь групп, хотя полный контекст и проверка образцов
поддерживали три. В старых экспортированных признаках без `previewMs`
используется время акустического региона. Редкие согласованные голоса из
независимых реплик по-прежнему проходят отдельную проверку поддержки.

Образцы для прослушивания выбираются из уверенной речи без наложения. Весь
фрагмент 2,5 с должен помещаться внутри одного голоса с запасом по краям;
смешанный отпечаток или слишком короткий чистый участок не используются.

### Полный акустический прогон на телефоне

`LongAudioDiarizationDeviceTest` — opt-in диагностика длинной записи с
потоковым PCM, foreground-службой, сохранением прогресса и отчётами о памяти,
температуре и времени. Она не вызывает Whisper. В `eval/acoustic/<fixture>/`
передаются `source.m4a` и, для отдельного замера нейросетей, `source.s16`
(16 кГц, mono, PCM16 little endian):

```bash
adb shell am instrument -w -e class com.example.guzlikvoice.LongAudioDiarizationDeviceTest#extractWholeRecording -e longAudio true -e predecoded true -e fixture interview-2026-11-04 ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
adb shell am instrument -w -e class com.example.guzlikvoice.BoundaryRefinementDeviceTest -e boundaryAudit true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
```

При `predecoded=true` оба нейросетевых прохода выполняются на телефоне, а AAC
предварительно преобразован в PCM. `decode_ms=0`, `input_copy_ms` измеряет
подготовку. Такой результат не является полным замером импорта M4A вместе с
распознаванием речи. Без флага тест отдельно декодирует весь M4A. Для сравнения
декодирования и побайтного контроля PCM предусмотрен
`compareDecoderSourceLocations -e decoderAudit true`; при наличии
`decoder-baseline-prefix.pcm` дополнительно сверяется минута исходного PCM.

Результаты: `phone-full-evidence.json`, `phone-full-result.json`,
`long-status.json`. `BoundaryRefinementDeviceTest` использует эти признаки,
локальный PCM и разрешённую историческую фикстуру с завершённым вторым
проходом. Он прерывает второй проход, восстанавливает его через Android
Keystore и сравнивает признаки и интервалы с непрерывным запуском. Отдельно
проверяет сохранность ручной правки и отсутствие повторного автоматического
запуска после конфликта.

Для настройки ORT на человеческом монтаже вместо синтетики:

```bash
adb shell am instrument -w -e class com.example.guzlikvoice.DiarizationQualityDeviceTest#onnxThreadComparison -e threadAudit true -e threadFixture interview_validation_montage.s16 ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
```

Сравниваются 2/4/4/2 потока. Профиль меняется только при заметном выигрыше и
совпадении разметки; настройка одного параметра не сбрасывает остальные.
Не запускать сравнительные замеры параллельно с другим анализом на телефоне.
Opt-in JVM-проверки с локальными фикстурами всегда выполняются заново: Gradle
не должен брать предыдущий результат, если меняется внешний диагностический
файл.

### Сквозной аудит действий Android-приложения

`FullUserFlowDeviceTest` запускается только явно и только в `.dev`. Он использует
свои временные записи, 32-секундную копию разрешённой локальной PCM-фикстуры
`eval/acoustic/interview-2026-11-04/source.s16` и удаляет свои записи и созданные
системные экспорты. Кеш экспорта также очищается обычным `pruneOldExports`.
Для UI телефон должен быть разблокирован. Тест удерживает экран включённым,
открывает приложение штатным launcher-входом MIUI и пишет этапы в `FullUserFlow`.

```bash
adb shell am instrument -w -e class com.example.guzlikvoice.FullUserFlowDeviceTest#importEditTimeLinksQuestionExportRotationAndDiarization -e fullFlow true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
adb shell am instrument -w -e class com.example.guzlikvoice.FullUserFlowDeviceTest#legacySrtUsesBoundedAsrAndCachesTimestamps -e legacyFlow true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
# Только явная установка штатной публичной модели помощника, с проверкой SHA-256 и докачкой:
adb shell am instrument -w -e class com.example.guzlikvoice.FullUserFlowDeviceTest#prepareAssistantForFullFlow -e downloadAssistant true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
adb shell am instrument -w -e class com.example.guzlikvoice.FullUserFlowDeviceTest#assistantNoteQuestionProtocolAndPdf -e assistantFlow true ru.guzlikvoice.app.dev.test/androidx.test.runner.AndroidJUnitRunner
```

Проверяемые цепочки:

- Реальный импорт и Whisper → ручная правка → тайм-коды без замены текста →
  вопросы по актуальному тексту → Word с закрытием исходной карточки.
- Нажатие «Поделиться» после закрытия карточки: `content://`, право чтения
  и доступный поток файла. Intent перехватывается тестом, получатель не выбирается.
- Открытый выбор формата → пересоздание активности → экспорт аудио с побайтной
  сверкой → автоматическая диаризация → повторное включение тайм-кодов.
- Старая запись без сегментов → потоковое распознавание для SRT → сохранение
  тайм-кодов для повторного использования, без изменения ручного текста.
- «Выделить главное» → новая запись появляется за открытым диалогом выбора →
  анализ именно выбранного снимка записей. Настоящая генерация проверяется
  на синтетическом тексте с однозначной задачей.
- Протокол → закрытие его окна до завершения → сохранение; вопрос → поворот
  во время генерации → ответ; экспорт PDF после сохранённого протокола.

Отчёты: `eval/out/full-user-flow.json`, `legacy-srt-flow.json`,
`assistant-user-flow.json`. Успешное распознавание и корректность всех переходов
проверяются отдельно от абсолютной точности ASR/диаризации на всём аудио.

JVM-регрессии дополнительно проверяют незавершённые загрузки MediaStore,
коллизии имён экспорта, смену даты анализа, правку/удаление/защиту источника,
отмену, устаревшие ответы и удержание общей модели ожидающими заданиями и UI
после поворота. Экспорт работает через scope активности, а UI не обращается
к `requireContext()` уже закрытого листа. Длительное копирование выполняется
в IO; подготовленные файлы каждого экспорта имеют отдельный каталог кеша.
